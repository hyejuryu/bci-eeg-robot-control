# Session 10

## 1. Objectives

* Install and run OpenBCI GUI on Windows 11.
* Connect OpenBCI Cyton to OpenBCI GUI through the USB dongle.
* Confirm that the CYTON live data source and manual serial connection work.
* Confirm that the board-to-GUI live streaming path works.
* Check basic GUI Hardware Settings relevant to the initial EEG setup.
* Assemble and test the initial two-channel posterior headband montage:

  * Ch1 / N1P: posterior-left headband position
  * Ch2 / N2P: posterior-right headband position
  * SRB / SRB2 function: one earclip reference
  * BIAS: opposite earclip
* Assess whether the initial posterior dry-comb montage can produce stable, non-flat, non-railed scalp-contact waveforms.
* Use diagnostic electrode/contact tests to separate GUI, board, channel, cable, electrode, and scalp-contact issues.
* Document the confirmed acquisition path, unresolved bottleneck, and revised next steps.

Feature-level EEG interpretation is out of scope for this session.

## 2. Research question

Which parts of the OpenBCI Cyton acquisition chain can be confirmed during the initial GUI connection test, and where does the first acquisition bottleneck appear?

This session focuses on acquisition readiness rather than EEG feature interpretation.

## 3. What I studied

* OpenBCI GUI installation and Cyton connection workflow on Windows 11
* CYTON live data source selection and manual serial connection through COM3
* Difference between board-to-GUI live streaming and usable body-connected EEG acquisition
* Initial two-channel posterior montage using Ch1/N1P, Ch2/N2P, SRB reference, and BIAS
* Railed / Near Railed / flat waveform behavior during early acquisition checks
* Layered troubleshooting of the acquisition chain:

  ```text
  GUI connection
  → board streaming
  → channel path
  → cable / electrode path
  → reference / BIAS contact
  → scalp-contact condition
  ```

* Forehead flat-electrode testing as a simplified diagnostic condition for Ch1 and Ch2
* Cable and electrode swap testing to separate channel, cable, and electrode-contact issues
* Decision to treat posterior dry-comb scalp contact as the main unresolved bottleneck under the current hair/contact conditions

Session 10 confirmed the Cyton-to-GUI acquisition path and used forehead flat-electrode diagnostics to separate acquisition-path issues from posterior dry-comb contact issues.

## 4. Key takeaways

### 1. Cyton-to-GUI streaming path was confirmed

OpenBCI GUI was installed and launched successfully on Windows 11.

The GUI detected the CYTON live data source, and manual serial connection through COM3 succeeded.

The board-only stream test showed live signals in the Time Series widget, and accelerometer values were visible.

This confirms the following acquisition path:

```text
Cyton board
→ USB dongle
→ COM3 serial connection
→ OpenBCI GUI
→ live data stream
```

The moving traces observed during the board-only stream test were treated as floating-input activity and environmental/electrical noise, not physiological EEG, because no body-connected electrode/reference montage was present.

### 2. The initial posterior headband montage was assembled and mapped

The initial two-channel montage from Session 09 was physically assembled using the OpenBCI EEG Headband Kit.

The mapping used in this session was:

```text
Ch1 / N1P
= black snap cable
= posterior-left headband position
= comb electrode

Ch2 / N2P
= white snap cable
= posterior-right headband position
= comb electrode

SRB / SRB2 reference function
= left earclip

BIAS
= right earclip
```

The active electrode positions were recorded as approximate posterior-left and posterior-right headband positions, not exact 10–20 O1/O2 positions.

### 3. Forehead flat-electrode diagnostics separated the acquisition path from the posterior contact problem

The initial posterior dry-comb placement produced Railed/Near Railed channel states, so additional diagnostic tests were performed to isolate the source of the problem.

Touch tests and forehead flat-electrode tests showed that Ch1 and Ch2 were responsive under easier skin-contact conditions.

A known-good baseline was reproduced using:

```text
Ch1 / N1P
black snap cable
flat electrode A
forehead contact
SRB earclip unchanged
BIAS earclip unchanged
```

This produced a visible, non-flat, Not Railed Ch1 waveform during live streaming.

Cable and electrode swap tests reduced the likelihood that the main issue was the GUI connection, Cyton board, COM3 serial path, Ch1 input, Ch2 input, black snap cable, or white snap cable.

The same troubleshooting also identified one flat electrode as unreliable under the current setup.

### 4. Posterior dry-comb contact was identified as the main unresolved bottleneck

Posterior dry-comb acquisition remained Railed/Near Railed after testing:

```text
original comb electrode
→ second comb electrode
→ controlled hair separation
→ slight posterior position adjustment
```

Because the forehead flat-electrode baseline was reproducible, the remaining bottleneck was interpreted as posterior dry-comb scalp contact through hair.

This led to a revision of the contact strategy:

```text
current posterior dry-comb setup
→ unresolved under current hair/contact conditions

next posterior direction
→ contact-assisted setup using Ten20 paste and OpenBCI gold cup electrodes
```

No alpha, beta, PSD, attention, focus, or robot-control interpretation was performed.

## 5. My understanding

Session 10 clarified that early acquisition troubleshooting should first verify whether the observed live signal is usable, before moving to any EEG feature interpretation.

In this session, `Railed`, `Near Railed`, flat traces, and `Not Railed` states were used as practical sanity-check indicators. They helped distinguish between:

```text
live stream present
→ channel/cable/electrode path responsive
→ contact condition usable enough for recording
```

Forehead flat-electrode testing provided an easier contact condition and helped separate channel/cable problems from posterior scalp-contact problems. Because Ch1 and Ch2 worked under this simplified condition, the remaining posterior issue is more likely related to dry-comb contact through hair than to the GUI, COM port, Cyton board, or basic channel path.

For the next stage, the project should continue with infrastructure work using a known-good montage instead of forcing feature-level interpretation from an unstable posterior setup.


## 6. Questions / unclear points

* Would impedance checking in OpenBCI GUI help quantify the posterior contact problem?
* How should contact-assisted posterior acquisition using Ten20 paste and/or OpenBCI gold cup electrodes be tested and documented?
* How should stable posterior acquisition criteria be defined before eyes-open / eyes-closed recording?
* How should raw data file location, format, timestamp handling, and montage metadata be documented in the BrainFlow pipeline?
* Should the current posterior headband position be retained, adjusted, or replaced when the contact-assisted setup is tested?

* Treat Session 10 as closed with the conclusion that the Cyton-to-GUI acquisition path was confirmed and posterior dry-comb contact remains unresolved.

* Begin Session 11 with BrainFlow-based acquisition pipeline development using the known-good Ch1 forehead flat-electrode montage:

  ```text

  black snap cable
  flat electrode A
  forehead contact
  SRB earclip unchanged
  BIAS earclip unchanged
  Ch2–Ch8 off or ignored
  ```

* Stop further pressure-based posterior dry-comb troubleshooting under the current setup.
* Test posterior contact-assisted acquisition when Ten20 paste and/or OpenBCI gold cup electrodes are available.

* Do not perform eyes-open / eyes-closed alpha reactivity, PSD analysis, beta/alpha comparison, focus-state interpretation, or robot-control testing until stable posterior acquisition is confirmed.
