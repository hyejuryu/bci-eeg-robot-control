# Session 13

- Planned period: 2026.07.13–2026.07.15
- Actual work dates: 2026.07.12–2026.07.15
- Status: completed

## 1. Objectives

- Extend the condition-level posterior alpha workflow from Session 07 into a window-level feature time series.
- Generate 2-second windows with a 1-second step within the T0 interval and calculate `posterior_alpha_mean_psd` for each window.
- Save window-level features as CSV, analysis settings and descriptive summaries as JSON, and feature trajectories as a time-series figure.

Threshold, smoothing, dwell time, command generation, and parameter comparison are outside the scope of this session.

## 2. Research question

Can the existing condition-level posterior alpha workflow be converted into a reproducible window-level feature time series?

As a secondary check, this session also examined whether the eyes-closed > eyes-open direction observed in Session 07 remained present in the window-level summary.

## 3. Analysis configuration

| Item | Setting |
|---|---|
| Data | EEGBCI Subject 1, Runs 1–2 |
| Conditions | Eyes-open / eyes-closed baseline |
| Preprocessing | Full-run 1–40 Hz filtering, six posterior channels |
| Posterior channels | Po3., Poz., Po4., O1.., Oz.., O2.. |
| Annotation | T0, 0.0–60.2 s |
| Outer window | 2.0 s length, 1.0 s step, 59 windows per run |
| Welch | 160-sample segment, 80-sample overlap, 160-point FFT |
| PSD range | 1–40 Hz |
| Feature band | 8 ≤ f < 13 Hz |
| Feature | `posterior_alpha_mean_psd`, V²/Hz |

## 4. Implementation

The pipeline was implemented and checked in the following order:

```text
raw loading
→ annotation and channel validation
→ full-run filtering
→ window-bound generation
→ actual window slicing
→ first-window Welch PSD validation
→ first-window alpha-feature validation
→ feature extraction over all windows
→ CSV, JSON, and figure export
````

The main array shapes were:

```text
posterior run data:  (6, 9760)
one outer window:    (6, 320)
Welch PSD, 1–40 Hz:  (6, 40)
posterior mean PSD:  (40,)
alpha PSD values:    (5,)
final window feature: scalar
```

For each window, the feature was calculated in two averaging steps:

```text
1. Mean PSD across the six posterior channels at each frequency.
2. Mean of the resulting posterior PSD values over 8 ≤ f < 13 Hz.
```

Intermediate shapes and the first-window output were checked before the same calculation was extended to all windows.

## 5. Results

Each run produced 59 window-level feature rows, resulting in 118 rows in total.

| Baseline eyes closed | 5.4975e-10 | 5.0383e-10 |             2.5234e-10 | 1.6049e-10 | 1.2661e-09 |

The ratio between the condition-level window-feature means was:

```text
eyes closed / eyes open ≈ 12.25
```

The time-series figure showed that the eyes-closed feature remained generally higher than the eyes-open feature across the run.

The simple min–max ranges were not fully separated:

```text
eyes-open maximum:  2.2325e-10 V²/Hz
eyes-closed minimum: 1.6049e-10 V²/Hz
```

This confirms range overlap, but the full distribution overlap was not quantified in this session.

## 6. Key takeaways

### 1. The condition direction from Session 07 was retained in the window-level summary

Session 07 used one PSD estimate for each full run, while Session 13 summarized features calculated from overlapping windows with explicitly defined Welch parameters. The numerical values therefore represent different calculations.

The comparison is limited to directional consistency:

```text
Session 07: eyes closed / eyes open ≈ 11.54
Session 13: eyes closed / eyes open ≈ 12.25
```

Both analyses showed higher posterior alpha feature values in the eyes-closed condition.

### 2. Windowing added temporal information to the previous condition-level analysis

Session 07 represented the recording mainly along the frequency axis and showed the posterior alpha peak within the full run.

Session 13 reduced the selected alpha-frequency information to one scalar per window and represented it along the time axis.

```text
Session 07:
frequency → PSD

Session 13:
time → posterior alpha feature
```

The two representations provide complementary information. The Session 13 time series shows when the alpha feature changed, while the detailed frequency structure within 8–13 Hz is no longer visible in the feature figure.

### 3. The two conditions showed partial range overlap at the window level

The eyes-open maximum was higher than the eyes-closed minimum. Therefore, the difference between condition means does not imply that every individual window can be separated using one simple threshold.

This session confirmed min–max range overlap only. The amount and structure of distribution overlap remain to be examined.

## 7. My understanding

Session 13 converted one feature per run into a time-ordered feature stream. This stream provides the input structure needed for later threshold-based control.

However, the current condition means and min–max values are not sufficient for threshold selection. The two conditions showed partial range overlap, and the current feature stream depends on a fixed 2-second window and 1-second step.

Window length affects the time span represented by each feature and the minimum amount of data required before the feature can be computed. Step size affects the update interval and the amount of data shared by adjacent windows.

Session 14 should therefore compare window length and step size and examine their effects on feature variability and distribution overlap. The resulting evidence can then be used in Session 15 to define threshold, smoothing, and dwell-time rules.

## 8. Questions / unclear points

* How do window length and step size affect within-condition variability and distribution overlap?
* How should overlap between the eyes-open and eyes-closed feature distributions be quantified?
* Will the same condition direction remain when the analysis is extended to other subjects?
* Will normalization be needed when absolute PSD features are compared across subjects or recordings?

## 9. Next actions

Session 14 will focus on:

* comparing candidate window lengths;
* comparing candidate step sizes;
* examining condition-level feature distributions;
* evaluating within-condition variability;
* visualizing or quantifying distribution overlap;
* documenting the effects of parameter changes on window count, temporal resolution, and feature behavior.

Threshold, smoothing, and dwell-time logic will be addressed after the feature distributions and window parameters have been reviewed.
