# Session 17 — Arduino Servo Gripper Actuator Validation

- **Planned period:** 2026-07-23 to 2026-07-24
- **Actual work date:** 2026-07-25
- **Documentation finalized:** 2026-07-28
- **Status:** Completed
- **Related sessions:**
  - Session 15: Offline EEG-derived command-state generation
  - Session 18: Python–Arduino serial communication
  - Session 19: Stored EEG-derived command replay

## 1. Objective

Establish and validate a minimum Arduino–servo–gripper actuator
configuration supporting OPEN, CLOSE, and STOP states, and freeze the
hardware and motion configuration for subsequent serial control.

## 2. Scope

This session covered Arduino board validation, external servo-power
configuration, unloaded servo testing, mechanical gripper assembly,
commanded endpoint calibration, and Arduino-internal OPEN/CLOSE/STOP
actuator testing.

Python serial communication, EEG-derived command replay, end-to-end
latency measurement, grip-force measurement, and object-retention testing
were not included.

## 3. Final configuration

| Item | Selected configuration |
|---|---|
| Board | Arduino Uno R3-compatible board |
| Arduino IDE | 2.3.10 |
| Port during Session 17 | COM4 |
| Servo | Tower Pro SG90, `S17-SERVO-A` |
| Servo signal pin | D9 |
| Arduino power | Computer USB |
| Servo power | External 5 V, 2 A adapter |
| Ground reference | Arduino GND connected to the external servo-power GND rail |
| Capacitor | 1000 µF, 16 V electrolytic capacitor |
| CLOSE endpoint | 60° commanded angle |
| Startup angle | 90° commanded angle |
| OPEN endpoint | 120° commanded angle |
| Angle direction | Increasing angle opened the gripper; decreasing angle closed it |
| Motion update | 2° every 50 ms |
| STOP behavior | Stop further commanded-angle updates |
| Endpoint behavior | Clamp the commanded angle to the 60–120° range |

The angle values are inputs to `Servo.write()` and were not independently
measured as physical servo-shaft angles.

## 4. Validation procedure

1. Validated Arduino board detection, sketch upload, Blink execution,
   and reset behavior.
2. Checked adapter polarity, barrel-terminal polarity, breadboard-rail
   continuity, and approximately nominal 5 V output.
3. Tested the SG90 without the gripper over a narrow commanded-angle range.
4. Assembled the acrylic gripper and checked manual mechanical movement.
5. Commanded the servo to 90° and aligned the gripper near the middle of
   its mechanical travel before fixing the servo horn.
6. Tested commanded angles from 60° to 120° and selected the OPEN, CLOSE,
   and startup values.
7. Ran an Arduino-internal sequence covering OPEN, CLOSE, STOP, direction
   reversal, duplicate-state handling, and endpoint clamping.
8. Observed startup and reset behavior.
9. Repeated the final configuration during endpoint calibration and
   actuator-state testing.

## 5. Results and observations

| Validation | Observation | Result |
|---|---|---|
| Board smoke test | Blink compiled and uploaded using Arduino IDE 2.3.10 on COM4. The onboard LED resumed regular blinking after reset. | PASS |
| External power path | Adapter polarity, screw-terminal polarity, and breadboard-rail continuity were confirmed. An output near 5 V was observed during the check, but the exact no-load reading was not recorded. | PASS |
| Unloaded servo test | The SG90 moved between commanded angles of 80° and 100° for five cycles and returned to 90°. No board reset, USB disconnection, persistent buzzing, or obvious abnormal heating was observed. | PASS |
| Mechanical dry fit | The assembled gripper could be opened and closed manually without clear mid-range interference or acrylic damage. | PASS |
| Endpoint calibration | Increasing the commanded angle opened the gripper, while decreasing it closed the gripper. The tested 60–120° range operated without observed persistent buzzing or mechanical interference. | PASS |
| Actuator-state test | OPEN, CLOSE, STOP, direction reversal, duplicate-state handling, and endpoint clamping were observed in the Arduino-internal test sequence. | PASS |
| Startup/reset test | A brief and repeatable initial displacement was observed after startup/reset. The displacement remained self-limited and was not followed by sustained oscillation, endpoint overrun, or persistent stall. | PASS |
| Repeated operation | The final configuration was operated repeatedly during calibration and state testing without observed board reset, persistent stall, gear skip, or out-of-range motion. | PASS |

The repeated operations were part of calibration and functional testing;
they were not recorded as a separately counted cycle or reliability
protocol.

## 6. Interpretation

The staged board, external-power, unloaded-servo, and loaded-gripper checks
established separate functional baselines before the final actuator-state
test. This sequence supported fault isolation between the upload path,
servo-power path, servo operation, and mechanical gripper configuration.

The selected 60–120° commanded range provided sufficient travel for the
Session 17 OPEN/CLOSE demonstration without observed persistent stall,
buzzing, gear skip, or linkage interference. A brief and repeatable
startup/reset displacement remained, but it did not develop into sustained
instability.

## 7. Decisions

- Selected `S17-SERVO-A` as the actuator-v0.1 servo unit.
- Fixed D9 as the servo signal pin.
- Retained USB power for the Arduino board and an external 5 V rail for
  the servo.
- Connected Arduino GND and the external servo-power GND rail as a common
  signal reference.
- Selected 60° as the commanded CLOSE endpoint.
- Selected 120° as the commanded OPEN endpoint.
- Selected 90° as the startup commanded angle.
- Retained incremental 2° commanded-angle updates at 50 ms intervals.
- Defined STOP as termination of further commanded-angle updates.
- Retained endpoint clamping, duplicate-state handling, and direction
  reversal behavior for Session 18.

## 8. Remaining issue

The cause of the brief startup/reset displacement was not isolated.
Servo initialization and mechanical play in the acrylic gear and linkage
assembly are possible contributors. The behavior will be checked again
during the serial-port-open test in Session 18.

## 9. Next actions

Session 18 will retain the Session 17 actuator-v0.1 hardware and motion
configuration. The Arduino-internal test sequence will be replaced by
Python serial commands using the vocabulary `OPEN`, `CLOSE`, and `STOP`.

Session 18 will validate:

- Python-to-Arduino command transmission
- Arduino command parsing
- ACK responses
- invalid-command handling
- serial-port-open reset behavior
- basic command, acknowledgment, and actuator-event logging
