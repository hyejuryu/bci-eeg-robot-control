# Session 10

## 1. Objectives

* Install and run OpenBCI GUI on Windows 11.
* Connect OpenBCI Cyton to OpenBCI GUI through the USB dongle.
* Confirm that the CYTON live data source and manual serial connection work.
* Confirm that the board-to-GUI live streaming path works.
* Check basic GUI Hardware Settings relevant to the initial EEG setup.
* Assemble and test the initial two-channel posterior headband montage:

  * Ch1 / N1P: posterior-left headband position
  * Ch2 / N2P: posterior-right headband position
  * SRB / SRB2 function: one earclip reference
  * BIAS: opposite earclip
* Assess whether the initial posterior dry-comb montage can produce stable, non-flat, non-railed scalp-contact waveforms.
* Use diagnostic electrode/contact tests to separate GUI, board, channel, cable, electrode, and scalp-contact issues.
* Document the confirmed acquisition path, unresolved bottleneck, and revised next steps.

Feature-level EEG interpretation is out of scope for this session.

## 2. Research question

Which parts of the OpenBCI Cyton acquisition chain can be confirmed during the initial GUI connection test, and where does the first acquisition bottleneck appear?

This session focuses on acquisition readiness rather than EEG feature interpretation.

## 3. What I studied

* OpenBCI GUI installation and launch on Windows 11
* CYTON live data source selection and USB dongle connection workflow
* Manual serial connection through the USB dongle / COM port
* Board-only live stream confirmation and its interpretation boundary
* Basic GUI Hardware Settings for the initial Cyton setup
* Initial body-connected montage setup using:

  * two posterior comb electrodes
  * one earclip reference
  * one BIAS earclip connection
* Relationship between Cyton pin mapping, channel mapping, and GUI channel display
* Difference between live data streaming and usable EEG acquisition
* Railed / Near Railed / flat channel behavior during initial posterior headband placement
* Layer-by-layer troubleshooting of:

  * GUI connection
  * board streaming
  * Cyton pin / channel mapping
  * Ch1 / Ch2 channel responsiveness
  * snap cable function
  * flat electrode reliability
  * reference / BIAS contact
  * posterior dry-comb scalp contact
* Forehead flat-electrode diagnostic testing for Ch1 and Ch2
* Cable / electrode swap testing to separate channel, cable, and electrode-contact issues
* Posterior dry-comb retry using two comb electrodes, hair-parting, and slight position adjustment
* Decision-making around whether to continue with dry-comb posterior contact or revise the contact strategy

Session 10 confirmed GUI launch, COM3 manual connection, live streaming, accelerometer visibility, Ch1/Ch2 channel responsiveness, and reproducible Ch1 forehead flat-electrode acquisition using the working flat electrode. Posterior dry-comb acquisition remained Railed/Near Railed despite repeated contact attempts. The unresolved issue was therefore interpreted as posterior dry-comb scalp contact through hair, not as a GUI, board, COM port, Ch1 input path, or black snap cable failure.

## 4. Key takeaways

### 1. Cyton-to-GUI streaming path was confirmed

OpenBCI GUI was installed and launched successfully on Windows 11.

The GUI detected the CYTON live data source, and manual serial connection through COM3 succeeded.

The board-only stream test showed live signals in the Time Series widget, and accelerometer values were visible.

This confirms the following acquisition path:

```text
Cyton board
→ USB dongle
→ COM3 serial connection
→ OpenBCI GUI
→ live data stream
```

The moving traces observed during the board-only stream test were treated as floating-input activity and environmental/electrical noise, not physiological EEG, because no body-connected electrode/reference montage was present.

### 2. The initial posterior headband montage was assembled and mapped

The initial two-channel montage from Session 09 was physically assembled using the OpenBCI EEG Headband Kit.

The mapping used in this session was:

```text
Ch1 / N1P
= black snap cable
= posterior-left headband position
= comb electrode

Ch2 / N2P
= white snap cable
= posterior-right headband position
= comb electrode

SRB / SRB2 reference function
= left earclip

BIAS
= right earclip
```

The active electrode positions were recorded as approximate posterior-left and posterior-right headband positions, not exact 10–20 O1/O2 positions.

### 3. Forehead flat-electrode diagnostics separated the acquisition path from the posterior contact problem

The initial posterior dry-comb placement produced Railed/Near Railed channel states, so additional diagnostic tests were performed to isolate the source of the problem.

Touch tests and forehead flat-electrode tests showed that Ch1 and Ch2 were responsive under easier skin-contact conditions.

A known-good baseline was reproduced using:

```text
Ch1 / N1P
black snap cable
flat electrode A
forehead contact
SRB earclip unchanged
BIAS earclip unchanged
```

This produced a visible, non-flat, Not Railed Ch1 waveform during live streaming.

Cable and electrode swap tests reduced the likelihood that the main issue was the GUI connection, Cyton board, COM3 serial path, Ch1 input, Ch2 input, black snap cable, or white snap cable.

The same troubleshooting also identified one flat electrode as unreliable under the current setup.

### 4. Posterior dry-comb contact was identified as the main unresolved bottleneck

Posterior dry-comb acquisition remained Railed/Near Railed after testing:

```text
original comb electrode
→ second comb electrode
→ controlled hair separation
→ slight posterior position adjustment
```

Because the forehead flat-electrode baseline was reproducible, the remaining bottleneck was interpreted as posterior dry-comb scalp contact through hair.

This led to a revision of the contact strategy:

```text
current posterior dry-comb setup
→ unresolved under current hair/contact conditions

next posterior direction
→ contact-assisted setup using Ten20 paste and OpenBCI gold cup electrodes
```

No alpha, beta, PSD, attention, focus, or robot-control interpretation was performed.

## 5. My understanding

### 1. Physical acquisition requires both path confirmation and contact validation

In previous sessions, EEG data was already available as public dataset files.

In Session 10, the acquisition chain had to be physically assembled and checked:

```text
body
→ electrode
→ snap cable
→ Cyton input / SRB / BIAS
→ Cyton board
→ USB dongle
→ OpenBCI GUI
→ live data stream
```

This showed that live streaming alone is not enough. A usable EEG setup also requires stable electrode-skin contact and a clearly documented montage.

### 2. Hardware troubleshooting must isolate variables before changing the plan

The posterior dry-comb setup did not work reliably, but the session did not treat this as a general acquisition failure.

Instead, the problem was separated layer by layer:

```text
GUI connection
→ board streaming
→ channel path
→ cable path
→ electrode reliability
→ reference / BIAS contact
→ scalp-contact condition
```

This approach made it possible to distinguish a working acquisition path from an unresolved posterior contact condition.

The session also showed that changing equipment or contact method should be based on troubleshooting evidence, not on a single failed placement attempt.

### 3. The experimental plan needs controlled flexibility

The original plan expected posterior dry-comb acquisition to support later eyes-open / eyes-closed alpha sanity checks.

However, Session 10 showed that the current posterior dry-comb method is not reliable enough for feature-level analysis.

The plan was therefore adjusted without abandoning the overall project:

```text
BrainFlow acquisition pipeline
→ proceed using a known-good forehead flat-electrode montage

posterior alpha sanity check
→ defer until contact-assisted posterior acquisition is available
```

This keeps the project moving while avoiding premature EEG feature interpretation.

The current boundary is:

```text
Feature-level posterior EEG analysis remains out of scope until the intended posterior montage shows stable, non-flat, non-railed acquisition.
```

## 6. Questions / unclear points

* How can posterior dry-comb contact through hair be improved without causing discomfort or motion artifact?
* Would impedance checking in OpenBCI GUI help quantify the posterior contact problem?
* Is the current headband position too unstable for dry posterior comb acquisition?
* Should conductive gel/paste or another contact-improvement method be considered for posterior recording?
* How should stable acquisition criteria be defined before eyes-open / eyes-closed recording?
* How should the GUI recording file location and raw data format be documented once stable acquisition is achieved?

## 7. Next actions

* Close Session 10 with the conclusion that the Cyton-to-GUI acquisition path was confirmed, while posterior dry-comb contact remains unresolved.
* Keep the forehead flat-electrode baseline as the known-good acquisition condition for short-term pipeline development.
* Begin Session 11 with BrainFlow-based acquisition pipeline development using the known-good forehead flat-electrode montage.
* Document raw data saving, timestamp handling, file naming, channel metadata, montage metadata, and readback verification in Session 11.
* Keep Arduino, servo, and robot hardware disconnected during EEG acquisition work.
* Keep flat electrode B out of the main setup unless it is re-checked or replaced.
* Stop further pressure-based posterior dry-comb adjustment under the current setup.
* Use Ten20 paste for a contact-assisted posterior diagnostic test when it arrives.
* Use OpenBCI gold cup electrodes for a revised posterior contact-assisted montage when they arrive.
* Update `alpha-reactivity-montage-v0.1.md` only after the revised posterior contact strategy is actually tested or adopted.
* Do not perform eyes-open / eyes-closed alpha reactivity, PSD analysis, beta/alpha comparison, focus-state interpretation, or robot-control testing until stable posterior acquisition is confirmed.
