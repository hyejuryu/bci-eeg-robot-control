# Session 10

## 1. Objectives

* Install and run OpenBCI GUI on Windows 11.
* Connect OpenBCI Cyton to OpenBCI GUI through the USB dongle.
* Confirm that the CYTON live data source and manual serial connection work.
* Confirm that the board-to-GUI live streaming path works.
* Check basic GUI Hardware Settings relevant to the initial EEG setup.
* Assemble and test the initial two-channel posterior headband montage:

  * Ch1 / N1P: posterior-left headband position
  * Ch2 / N2P: posterior-right headband position
  * SRB / SRB2 function: one earclip reference
  * BIAS: opposite earclip
* Assess whether Ch1 and Ch2 can show stable, non-flat, non-railed scalp-contact waveforms.
* Document connection status, observed issues, and next troubleshooting steps.

Feature-level EEG interpretation is out of scope for this session.

## 2. Research question

Which parts of the OpenBCI Cyton acquisition chain can be confirmed during the initial GUI connection test, and where does the first acquisition bottleneck appear?

This session focuses on acquisition readiness rather than EEG feature interpretation.

## 3. What I studied

* OpenBCI GUI installation and launch on Windows 11
* CYTON live data source selection and USB dongle connection workflow
* Manual serial connection through the USB dongle / COM port
* Board-only live stream confirmation and its interpretation boundary
* Basic GUI Hardware Settings for the initial Cyton setup
* Initial body-connected montage setup using:

  * two posterior comb electrodes
  * one earclip reference
  * one BIAS earclip connection
* Relationship between Cyton pin mapping, channel mapping, and GUI channel display
* Difference between live data streaming and usable EEG acquisition
* Railed / flat channel behavior during initial posterior headband placement
* Layer-by-layer troubleshooting of:

  * hardware setting state
  * Cyton pin / channel mapping
  * electrode placement and contact
  * Ch1 / Ch2 touch response
* Dry comb electrode scalp-contact instability as the likely bottleneck in the initial posterior montage

Session 10 Day 1 confirmed GUI launch, COM3 manual connection, live streaming, accelerometer visibility, and Ch1/Ch2 touch response. Stable posterior dry-comb acquisition was not yet achieved, and detailed troubleshooting was separated into a setup log.

## 4. Key takeaways

### 1. Cyton-to-GUI streaming path was confirmed

OpenBCI GUI was installed and launched successfully on Windows 11.

The GUI detected the CYTON live data source, and manual serial connection through COM3 succeeded.

The board-only stream test showed live signals in the Time Series widget, and accelerometer values were visible.

This confirms the following acquisition path:

```text
Cyton board
→ USB dongle
→ COM3 serial connection
→ OpenBCI GUI
→ live data stream
```

The moving traces observed during the board-only stream test were treated as floating-input activity and environmental/electrical noise, not physiological EEG, because no body-connected electrode/reference montage was present.


### 2. The initial headband montage was assembled and mapped

The initial two-channel montage from Session 09 was physically assembled using the OpenBCI EEG Headband Kit.

The mapping used in this session was:

```text
Ch1 / N1P
= black snap cable
= posterior-left headband position
= comb electrode

Ch2 / N2P
= white snap cable
= posterior-right headband position
= comb electrode

SRB / SRB2 reference function
= left earclip

BIAS
= right earclip
```

The active electrode positions were recorded as approximate posterior-left and posterior-right headband positions, not exact 10–20 O1/O2 positions.

### 3. Ch1 and Ch2 channel paths responded to touch tests

During normal posterior headband placement, Ch1 and Ch2 remained railed and did not show stable scalp-contact waveforms.

However, direct touch tests on the Ch1 and Ch2 comb electrodes produced channel responses in the GUI.

This suggests that the following elements were likely functional:

```text
Ch1 / N1P path
Ch2 / N2P path
snap cables
comb electrodes
Cyton-to-GUI stream
```

Therefore, the main bottleneck was narrowed down to electrode-skin contact stability rather than GUI installation, COM port connection, or a completely broken channel path.

### 4. Stable posterior dry-comb EEG acquisition was not yet achieved

The intended posterior headband placement did not yet produce stable, non-flat, non-railed waveforms from Ch1 or Ch2.

The observed issue was consistent with unstable dry comb electrode contact through hair.

Therefore, Session 10 Day 1 should be treated as a partial success:

```text
Confirmed:
- OpenBCI GUI launch
- Cyton live data source
- COM3 manual connection
- live data streaming
- accelerometer visibility
- Ch1/Ch2 touch response

Not yet achieved:
- stable posterior scalp-contact waveform
- usable EEG acquisition from the intended montage
```

No EEG feature interpretation was performed.

## 5. My understanding

### 1. This session marked the transition from file-based analysis to physical acquisition

In previous sessions, EEG data was already available as public dataset files.

In Session 10, the acquisition chain had to be physically assembled and checked:

```text
body
→ electrode
→ snap cable
→ Cyton input / SRB / BIAS
→ Cyton board
→ USB dongle
→ OpenBCI GUI
→ live data stream
```

This made the physical setup part of the research process, not just a preparation step.

### 2. Montage documentation is necessary for reproducibility

The approximate posterior montage became more concrete during the physical setup.

The setup required specific operational choices:

```text
which headband position
which electrode type
which snap cable
which Cyton channel
which earclip reference
which BIAS connection
```

This clarified why channel mapping and montage documentation must be recorded before EEG feature interpretation.

### 3. Hardware troubleshooting requires layer-by-layer isolation and buffer time

Session 10 Day 1 confirmed that the Cyton-to-GUI streaming path worked.

The Ch1/Ch2 touch tests also suggested that the channel paths were responsive.

However, stable posterior dry-comb scalp contact was not yet achieved.

Because multiple elements are involved in EEG acquisition, troubleshooting should proceed by isolating one layer at a time:

```text
GUI connection
→ board streaming
→ channel path
→ reference / BIAS
→ electrode contact
→ stable scalp-contact waveform
```

Future OpenBCI sessions should include buffer time for contact instability, cable movement, channel settings, connector issues, screenshots, and metadata documentation.

The current boundary is:

```text
Feature-level analysis remains out of scope until at least one intended active channel shows a stable, non-flat, non-railed scalp-contact waveform.
```



## 6. Questions / unclear points

* Can Ch1 show a stable, non-railed waveform if the active electrode is moved from posterior hair-covered placement to a forehead skin-contact position?
* Is a flat snap electrode more appropriate than a comb electrode for the forehead contact diagnostic test?
* How much headband pressure is needed for stable dry comb electrode contact without causing discomfort?
* Would impedance checking in OpenBCI GUI help quantify the contact problem?
* Should Ch1 be stabilized first before adding Ch2?
* Is the posterior headband position itself too unstable for dry comb contact without additional preparation?
* How should the GUI recording file location and raw data format be documented once stable acquisition is achieved?

## 7. Next actions

* Safely disconnect the LiPo battery from the USB charger before any further Cyton testing.
* Do not perform body-connected EEG testing while the battery is charging.
* Keep Arduino, servo, and robot hardware disconnected during EEG acquisition.
* Continue Session 10 troubleshooting with a single-channel test first.
* Use only Ch1 / N1P with SRB earclip reference and BIAS earclip.
* Keep Ch3–Ch8 off or ignored.
* Temporarily keep Ch2 off or ignored until Ch1 is stable.
* First test Ch1 at a forehead skin-contact position to separate channel-path functionality from posterior dry-comb scalp-contact instability.
* If Ch1 shows a non-flat, non-railed waveform at the forehead, save a screenshot.
* Then retry Ch1 at the posterior comb electrode position.
* Add Ch2 only after Ch1 becomes stable.
* Do not perform eyes-open / eyes-closed alpha reactivity, PSD analysis, beta/alpha ratio calculation, focus-state interpretation, or robot-control testing yet.
